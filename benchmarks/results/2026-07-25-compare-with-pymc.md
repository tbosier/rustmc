## Model / workload

- Script: `examples/compare_with_pymc.py`
- Model: `y = beta * x + Normal(0, sigma)`, 1 estimated parameter (beta), N=10,000 observations.
- True/simulated values: `true_beta = 2.5`, `true_sigma = 1.0`.
- Estimated vs. fixed: `beta` is estimated on every engine; `sigma = 1.0` (the true simulated
  noise) is fixed/known on every engine — same parameter count (1) everywhere. No sigma
  asymmetry found in this script.
- Chains: 4 (all engines). Warmup/tune: 500 (all engines). Draws: 1000 (all engines).
- Seed: 42, explicit on every engine (`random_seed=42` for PyMC, `seed=42` for nutpie and rustmc).
- Threads/processes: rustmc uses Rayon's default thread pool (unset `RAYON_NUM_THREADS`, defaults
  to 24 logical CPUs) for its 4 chains; PyMC/nutpie use `cores` defaulting to 4 (one process per
  chain).

## Result

- Raw output log: see `benchmarks/results/compare_with_pymc.py.log` (generated by
  `python examples/run_benchmarks.py`).
- Honest conclusion: on this small (1-parameter) model, rustmc is genuinely faster by ESS/s than
  both PyMC configurations (7.9x vs. default NUTS, 7.9x vs. nutpie — recompute from the ESS/s
  column above). However, rustmc produced 22 divergences on an otherwise well-behaved model where
  both PyMC backends produced zero, on the identical model/data/seed. That is a real
  quality difference worth investigating in the sampler/step-size adaptation, not just a "rustmc
  wins" headline — see "Known limitations" in the PR description.
