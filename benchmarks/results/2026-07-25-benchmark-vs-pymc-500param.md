## Model / workload

- Script: `examples/benchmark_vs_pymc.py`
- Model: `y = intercept + X @ beta + Normal(0, sigma)`, 501 estimated parameters
  (1 intercept + 500 betas via faer `MatVecMul` on rustmc / `pm.math.dot` on PyMC),
  N=2,000 observations.
- True/simulated values: `true_beta ~ N(0, 0.1)` (500-vector), `true_sigma = 1.0`.
- Estimated vs. fixed: intercept and all 500 betas are estimated on every engine;
  `sigma = 1.0` (the true simulated noise) is fixed/known on every engine — same parameter
  count (501) everywhere.
- Chains: 2 (all engines, bumped from an original chains=1 so split R-hat is defined).
  Warmup: 500 (all engines). Draws: 500 (all engines).
- Seed: 42, explicit on every engine.
- Threads/processes: rustmc's Rayon default pool for 2 chains; PyMC/nutpie use 2 processes
  (chains, no explicit `cores=` so it defaults to `chains`).

## Result

- Raw output log: see `benchmarks/results/benchmark_vs_pymc.py.log` (generated by
  `python examples/run_benchmarks.py`).
- **Honest conclusion: rustmc is 3.2x slower than PyMC's default NUTS and 6.3x slower than
  PyMC+nutpie by ESS/s on this 500-parameter, faer-`MatVecMul`-backed model.** This
  contradicts any claim that rustmc's faer path is faster than PyMC at high parameter
  counts, at least at N=2,000 observations / 500 parameters on this CPU. rustmc also
  produced 7 divergences where both PyMC backends produced 0. This is the single most
  important honest result in this benchmark suite and should not be omitted from the
  README.
