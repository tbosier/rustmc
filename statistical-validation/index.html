    Statistical release checks

    This page describes the gate that has to pass before a release: a fixed set of models whose exact posteriors are known analytically, refitted and compared against them. It is for contributors and for anyone judging how much the samplers are checked. You do not need it to use the library.

    Run python -m benchmarks.validate_posteriors --output /tmp/posteriors.json after building rustmc. The command returns a nonzero status if a fit or gate fails.

    Four fixed datasets have analytic posterior moments: Normal location, correlated Gaussian regression, Beta–Bernoulli, and Gamma–Poisson. Each runs under three seeds. The run fails if any of those cases does not produce its three records, or if a case outside that list is attempted; the report's case_coverage block records what ran against what was required.

    Checks require R-hat <= 1.01, bulk and tail ESS >= 400, no divergences, and bounded errors in posterior means and covariance. Every parameter is checked separately, against the full range each diagnostic can take rather than only against its threshold. A missing, non-finite, non-numeric, or out-of-range R-hat or ESS for any single parameter fails the run on its own and names that parameter in the report; the bounds are derived from the estimators themselves, so a value outside them did not come from a fit. Divergence telemetry must be one whole non-negative count per chain, since a sum of counts can cancel and cannot show a missing chain. Failed values are kept in the report, written as JSON null where they are not finite. These checks compare with the posterior for the observed dataset, rather than only with the parameter that generated the data.

    A separate experiment draws regression coefficients from the stated prior, simulates data with NumPy, and refits each dataset. It retains parameter coverage and rank histograms, every attempted fit, and numerical or convergence failures. Coverage uses independent replicate counts and a stated conservative finite-sample bound. Rank histograms are exploratory because the retained MCMC draws are autocorrelated. A small experiment has limited power; passing is not proof of calibration for every model.

    The JSON records source revision, native module hash, versions, command, seeds, and reference values. CI runs 32 replicates and uploads the report even if a gate fails, including failures while building a case, failures while simulating a replicate, and diagnostics that cannot be serialized. No report is written if importing rustmc fails, or if the trailing git rev-parse and native-hash calls raise. The default local run uses 64. Increase the replicate count for a more precise study.

    The coverage check passes when each coefficient's 90% interval coverage lies within sqrt(ln(4000) / (2n)) of the nominal 0.90, where n is the replicate count. At the 32 replicates CI runs, that accepts any coverage from 0.54 to 1.00, so the per-PR run is a smoke check that catches only gross miscalibration. At the local default of 64 the accepted band is about 0.65 to 1.00, and 256 replicates narrow it to about 0.77 to 1.00. The band reaches 1.00 at every one of these counts, so over-wide intervals are not caught at all. The report records the tolerance it used as coverage_tolerance.

    The fixed reference cases above run at target_accept=0.95, not the shipped 0.80. The exactness gate below runs at the shipped defaults. The Rust recovery suite runs at the shipped target_accept=0.8, with its own draws, warmup and tree depths (2000 or 4000 draws, 1000 to 1500 warmup, tree depth 8 to 12), so it does not test the shipped draw and warmup counts.

    Exactness at the shipped defaults

    rust_core/tests/exactness.rs fits targets whose moments are known in closed form, so the only error left is Monte Carlo error. Every fit uses SamplerConfig::default() apart from the seed: NUTS, 4 chains, 500 warmup, 1000 draws, target_accept=0.8, metric auto, tree depth 10. A fit passes when it has no divergences, the bulk ESS of every series whose Monte Carlo standard error (MCSE) is used below is at least 400, and these standardized errors are all below 4 MCSE:

    • each coordinate's mean against its exact mean, with the MCSE the diagnostics report;
    • each coordinate's variance: the draws of (x - exact mean)^2 have expectation exactly the exact variance, so their mean is held to the same bound, with an MCSE from those squared draws' own effective sample size;
    • once per fit, the squared norm of the whitened draw. Each target is w = A x - c ~ Normal(0, I), so |w|^2 has expectation exactly the dimension. A bias spread thinly over many directions adds up here while the noise grows only as the square root of the dimension.

    How auto chooses a dense metric

    0.14.0 compared the condition number of a window's sample correlation matrix with a noise bound computed from the window's effective draws, counted from the average lag-one autocorrelation. On the 0.95 correlated target that count left fewer effective draws than dimensions, so the dense estimate was never trusted. Two other counts were tried and not kept: one for a covariance, n (1 - rho^2) / (1 + rho^2), went dense on a curved target and lost most of a fit's ESS there, and the least count over coordinates went dense on simulated noise and stayed diagonal when a single coordinate mixed slowly. The count itself was the weak point: draws whose coordinates mix at different speeds have no single effective sample size.

    0.15.0 scores both metrics on held-out draws instead. Each half of a window estimates a diagonal and a dense metric, and each estimate is scored by the condition number it leaves the other half's sample covariance. The dense metric is used when the geometric mean of its two scores is lower than the diagonal's: by any amount in the early windows, whose metric only samples the next window, and by a factor of 2 in the last window, whose metric the draws are sampled with. The metric installed, though, comes from the whole window, whose covariance also holds any shift between the halves' means, so a second check scores the whole-window diagonal and dense metrics, with the regularization they are installed with, on each half, and the block stays diagonal unless the dense one still conditions the halves better on average. Two halves correlated at 0.95 and centered 20 apart pass the first check, while the whole-window dense metric would leave them a condition number near 4000 against 39 for the diagonal one; the second check keeps them diagonal. The rule needs no estimate of the window's effective sample size, which the old rule's noise bound did. Each half must hold more draws than the vector has elements.

    What the rule cannot see is a direction that neither half has explored. When the chain mixes slowly along a direction off the coordinate axes, both halves understate its variance alike, and a dense estimate that shares the shortfall scores well. In simulated warmup windows of stationary AR(1) coordinates, 30 per case, two coordinates with identity covariance, one mixing at 0.99 and both rotated 45 degrees, went dense in 17 of 30 at a margin of 2 (30 of 30 at 0.999), where the old rule chose dense in none at 0.99 and 21 at 0.999. In 40 dimensions the same pattern, 20 slow coordinates rotated in pairs, went dense in none of 30 under the new rule and 30 of 30 under the old. The curved target below, which NUTS crosses slowly along its curve, is a real target where this can happen, and its fits moved both ways.

    In the other cases, the rule at a margin of 2 chose dense in none of the uncorrelated windows and in all 30 windows of every 0.95 correlated case, while the old rule chose dense in none of the 0.95 correlated windows whose coordinates mixed at 0.8. At a margin of 1, uncorrelated windows whose halves held barely more draws than dimensions went dense in 3 and 28 of 30, and the two-dimensional window with one coordinate at 0.9 in 12, which is why the last window asks for 2. The table is benchmarks/results/2026-10-19-auto-metric-noise.txt. It tests the rule on stationary draws, which real warmup draws are not.

    Power controls

    The fault-injection cargo feature (off by default, compiled out otherwise) adds two faults to the NUTS kernel. CI runs rust_core/tests/exactness_power.rs, which fits every gate case at its gate seed and the two seeds after it (18 fits) under each fault and requires a moment check to fail, meaning a finite standardized error of 4 MCSE or more; failing only the ESS floor or a divergence check does not count.

    • Biased multinomial merge: every merge of two subtrees, and every doubling, takes the newer subtree's proposal whatever the weights say. Required in at least 15 of the 18 fits.
    • Step size 30% too large without the Metropolis correction: after warmup the kernel integrates with 1.3 times the adapted step size and weights every non-divergent leaf equally. Required in all 18.
    cargo test --release -p rustmc_core --features fault-injection --test exactness_power

    Both faults were caught in all 18 fits. Over 200 more seeds per case (from 20,000), the gate caught:

    Case Biased merge: caught Per-coordinate checks alone Overstep: caught Per-coordinate checks alone
    100 independent normals, custom target 188/200 18/200 200/200 157/200
    100 independent normals, graph 190/200 31/200 200/200 168/200
    50-d correlation 0.8, custom target 200/200 20/200 200/200 0/200
    50-d correlation 0.95, custom target 200/200 182/200 200/200 0/200
    50-d correlation 0.95, graph 200/200 25/200 200/200 150/200
    10-coefficient regression, graph 195/200 52/200 200/200 186/200

    The per-coordinate checks alone missed most biased merges, and almost every overstep on the correlated custom-target cases: there the too-large step distorts the stiff whitened directions, which barely move any one coordinate's variance. The squared-norm check was added for that reason. On the 0.95 correlated graph case, where auto now chooses a dense metric, the per-coordinate checks alone catch 150 of 200 oversteps against 1 in 0.14.0. With the squared-norm check, the median size of its error was 13.6 to 21.5 MCSE under the overstep (smallest 10.0) and 5.9 to 11.6 MCSE under the biased merge. The biased merge is a mild fault on Gaussians, and the gate misses it in up to 12 fits in 200. That is why the CI test asks for 15 of 18 rather than all 18: from these rates, all 18 would turn it red on about 34% of changes that move the draws with nothing wrong, and 15 of 18 on about 0.04%. A correct sampler fails the gate on about 2% of fits, so it cannot reach 15. The run is recorded in benchmarks/results/2026-10-19-exactness-detection.log (101 s, on a shared machine); 0.14.0's is the 2026-10-14 log beside it.

    RUSTMC_EXACTNESS_SEEDS=200 cargo test --release -p rustmc_core --features fault-injection \
    --test exactness_power -- --ignored --nocapture detection_rate_over_seeds

    False-alarm rate

    The correct sampler was run on every case for 2000 seeds (10,000 to 11,999). The nominal rate is what the moment checks would give if every standardized error were an independent standard normal: two checks per coordinate and the squared norm, each beyond 4 with probability 6.3e-5. Expected nominal counts per 2000 fits are 25.3 for 100 dimensions, 12.8 for 50 and 2.6 for 10.

    100 independent normals, custom target 53 (2.65%) 53 (2.65%) 1.27% 0
    100 independent normals, graph 47 (2.35%) 47 (2.35%) 1.27% 0
    50-d correlation 0.8, custom target 35 (1.75%) 35 (1.75%) 0.64% 0
    50-d correlation 0.95, custom target 47 (2.35%) 21 (1.05%) 0.64% 26

    No fit diverged. The moment checks fail a correct sampler more often than nominal: 2.1, 1.9 and 2.7 times on the independent normals and the 0.8 correlated target, where the counts are large enough to tell. The excesses of 1.6 and 1.2 times on the 0.95 correlated target rest on 21 and 15 failures and are not clearly outside chance, and the regression's single failure is below nominal. Most of the excess is in the variance checks. Pooled over coordinates and seeds, the mean errors are close to what a correct MCSE predicts (4.5% to 4.9% beyond 2 MCSE against a nominal 4.55%, standard deviation 0.994 to 1.006), though on the 0.8 correlated target 0.020% were beyond 4 against 0.0063%. The variance errors have nearly the right spread (standard deviation 1.000 to 1.037) but a heavier lower tail: 0.005% to 0.048% beyond 4 MCSE, up to eight times nominal and above it in every case but the regression. 131 fits failed a variance check; the log names one as the reason in 130 of them, and each of those 130 was below the exact value (the 40 mean failures split 20 below, 20 above). The likely reason is that the squared deviations are right-skewed: a sample whose squared deviations happen to be small also has a small estimated MCSE, so the self-normalized error reaches far below zero more often than above. The ESS floor also fails on its own on the 0.95 correlated custom target, whose smallest bulk ESS at the defaults ranged from 410 to 720 over the ten seeds of the cost record below; on the graph path, where auto now goes dense, it ranged from 3479 to 4937, and the floor failed no fit there (13 in 0.14.0).

    Taking the six cases together, a correct sampler fails at least one of them about 10% of the time. The gate seeds are fixed, so CI is deterministic, but a change that moves the draws has about that chance of turning the gate red with nothing wrong. Before treating a red gate as a bug, run the study on the change and compare it with this table. The 12,000 fits took 545 s on a 24-thread AMD Ryzen 9 5900X shared with other work (496 s for 0.14.0's run); the tallies are in benchmarks/results/2026-10-19-exactness-false-alarm.json and the output, with every failing fit, in the .log beside it. 0.14.0's run is the 2026-10-14 pair.

    cargo test --release -p rustmc_core --test exactness -- --ignored --nocapture \
    false_alarm_rate_over_seeds

    Static HMC: an open finding

    The same checks on static HMC at its default 15 leapfrog steps are ignored tests, because HMC fails them. On the independent normals at seed 2102 the worst coordinate's bulk ESS is 6 and the largest R-hat 1.78: the adapted step size puts 15 steps near a full period of a standardized coordinate, so a transition returns almost to where it started. On the 0.8 correlated target at seed 2202 every coordinate's bulk ESS is at least 627, but the squared norm's is 110, below the floor, and the largest R-hat is 1.016. Whether that second failure is the same resonance has not been shown.

    cargo test --release -p rustmc_core --test exactness -- --ignored --nocapture hmc_

    Exact posteriors for three Gibbs samplers

    The local level, the seasonal local level and the Gaussian hierarchical mean are each checked against moments of their exact joint posterior, by a unit test in each sampler's module using rust_core/src/exact_reference.rs. Given its variances, each model is a sum of independent normal terms, so the observations' covariance is written from the model's definition, without the filter, FFBS or Gibbs conditionals the samplers use. A trapezoid rule over a grid of log variances, weighted by the inverse-gamma priors, gives the moments of the variances and, by Gaussian conditioning, of the latent means: the terminal level or state, and the hierarchy's population, group and program means.

    Two checks guard each grid, and a test fails if either does. Along each variance's axis in turn, the integral on every other point must agree with the full grid to 1e-4 of the quantities' standard deviations, so an axis too coarse for its posterior fails. The integral on a grid at least two units wider at each end must agree to 1e-6, so an axis that cuts off a tail fails. Agreement is evidence that the grid has converged, not a bound on its error. Separate unit tests check the integration against a conjugate variance's closed form and the conditioning against a normal update, both to 1e-9 or better, and check that a grid too coarse or too narrow is refused.

    Each test fits 4 chains of 25,000 draws on a short series or ragged collection with missing values. It compares each quantity's mean and variance, the covariance of every pair, and each variance times each latent's squared deviation, where a hierarchy's dependence between a spread and the means it governs shows: 11, 47 and 152 comparisons in the three tests. Each estimate must lie within a tolerance, below, in Monte Carlo standard errors of its exact value and rest on a bulk ESS of at least 400, as in the NUTS gate, so draws that never move or chains stuck apart fail. A mean's MCSE uses the exact standard deviation, so an outlier cannot widen its own tolerance. The second-moment checks have no exact fourth moments to use, estimate theirs from the draws, and a few symmetric outliers could still hide in them. Matching these moments is necessary for the right posterior, not sufficient: higher moments are not compared.

    Each test has two controls that must fail for the reason they exist. The variances' draws, compared with the prior's mean and variance, must miss them, so a sampler that ignored the data fails. The same draws with each quantity rotated by a different number of iterations, which keeps every marginal's values and takes the quantities' draws from different iterations, must miss a dependence check. The hierarchy gives each variance its own prior, a nonzero population prior mean and unequal, interleaved groups, and the seasonal test uses nonzero initial effects placed as documented, one cycle in forecast order. The initial states' independence and variances are taken from the constructor rather than checked.

    scripts/plant_gibbs_bugs.py plants 16 bugs of those kinds and in the conjugate updates' counts and sums, and counts one as caught only when its test ran and missed a moment, not when it failed only on the ESS floor or a control. Every one is caught; the narrowest, reading the initial seasonal effects in reverse, misses by 5.9 MCSE.

    Each comparison's tolerance is the normal quantile that would hold the chance of any of a test's comparisons missing to 0.1% if their standardized errors were normal, and never below 4 MCSE: 4.00, 4.25 and 4.51 in the three tests. Estimated MCMC errors are only roughly normal, so 0.1% is a target. At a flat 4 MCSE the hierarchy failed 4 of 100 seeds of the correct sampler, each by a single comparison at 4.1 to 4.3, which is how the rule was chosen. scripts/plant_gibbs_bugs.py --seeds 100 101 reruns each test on seed offsets 101 to 200, which were not used to choose it: 1 of the 300 runs failed, the seasonal test at offset 161 (sampler seed 168), by one comparison at 4.42 MCSE. One failure in 300 neither confirms nor rules out the target. The committed tests use fixed seeds, so a chance failure can only appear when a change moves the samplers' draws.

    These are small fixed datasets. They check that each sampler targets the right posterior, not how fast it mixes on long series. The hierarchy's test integrates about 2.1 million grid points; the three tests together took 16 seconds in a release build on a 12-core Ryzen 9 5900X. CI runs them on Linux only.

    Known limitation: forecasting samplers' mixing

    None of these gates covers the forecasting samplers' mixing. Several Gibbs/FFBS samplers mix their state variances slowly, including the local linear trend fitted with exog; the plain local linear trend integrates its states out and does not. benchmarks/state_variance_mixing.py measures them, and the reference's slow state-variance mixing section lists which fits carry a known_limitation record.
